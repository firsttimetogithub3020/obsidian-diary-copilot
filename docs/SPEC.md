# Diary Copilot 產品規格

版本：v1（2026-11-11 定稿）

## 1. 目標

讓使用者用最低阻力每天寫英文日記：
- 想到什麼就寫，中文、英文都行
- AI 即時猜測「我接下來想寫什麼」，用英文呈現
- 卡住時主動提出引導問題
- 寫完一鍵整理成可長期累積、可被檢索的筆記

使用者：一人私用（未來可能分享給家人）。使用環境：Obsidian 桌面 App（Windows/Mac）與 Obsidian 手機 App（iOS/Android）。Obsidian 沒有網頁版，不考慮。

## 2. 核心體驗

### 2.1 書寫位置
- 不另開面板。外掛掛在 Obsidian 原生 Markdown 編輯器上，只在「日記資料夾」內的筆記啟用（預設 `Diary/`，可設定）。
- 指令「開啟今日日記」：開啟或建立 `Diary/YYYY-MM-DD.md`。
- Obsidian 原生自動存檔，外掛**不提供存檔按鈕**。

### 2.2 建議卡（1–3 張）
固定在編輯區底部，內容依序為：

| 卡 | 名稱 | 內容 | 顯示條件 |
|---|---|---|---|
| 1 | 猜下一句 | 依前文與語氣，最可能的下一句英文 | 永遠 |
| 2 | 另一個方向 | 另一種可能的發展（轉到感受、原因、細節…）；當前句過長時改為「拆句建議」 | 永遠 |
| 3 | 中 → 英 | 把最近一段中文改寫成自然的英文日記口吻（非逐字翻譯），並標示對應哪一段中文 | 游標附近有中文時 |

- 偏重「猜測」，不是翻譯工具。
- 每張卡最多兩行，超過則截斷；滑過（桌面）或長按（手機）展開。

### 2.3 採用方式
- **桌面**：游標後顯示卡 1 的灰色預測字（ghost text）；`Tab` 採用卡 1；`Alt+1/2/3`（可設定）採用對應卡；`Esc` 暫時隱藏。
- **手機**：不顯示灰字；卡片位於鍵盤正上方，點一下採用。
- 採用卡 3 時，**取代**對應的中文段落；採用卡 1、2 時，**插入**於游標處。
- 每次採用都記錄到當日的「採用紀錄」（見 §5）。

### 2.4 卡住時的引導問題
- 停筆超過 20 秒（可設定）且游標在文末時，卡片區改顯示 1 個引導問題，例如 "What surprised you today?"、"How did that make you feel?"。
- 問題依當天已寫內容產生；空白日記時用通用開場問題。
- 點擊問題：插入一行引用（`> question`）作為提示，不算入英文定稿。

## 3. 即時呈現策略（長文時仍保持快速、不跳動）

### 3.1 請求大小固定
每次請求只送：
- 目前這句（含游標前後）
- 前 2–3 句
- **前文摘要**：背景維護，每完成一段（換行）才重算；請求時直接附上快取的摘要
- 固定前綴（系統指令＋風格說明＋最近 3–5 篇日記摘要）：放在 prompt 最前面，利用模型的前綴快取

因此無論日記多長，延遲大致固定。

### 3.2 觸發時機
- 打完逗號、句號、問號、驚嘆號、中文標點或空格之後，停頓 400 ms 觸發（可設定）
- 長句一直沒有標點時：停頓 800 ms 也觸發
- 只是移動游標、選取文字：不觸發

### 3.3 請求管理
- 每個請求有遞增序號；回應序號不是最新就丟棄
- 使用者繼續輸入就 `abort()` 進行中的請求
- 串流回應：卡 1 先解析先顯示
- 相同上下文（hash）重複請求，直接用快取結果

### 3.4 本機前綴匹配（零延遲）
若使用者打的字正好是卡 1 內容的開頭，直接在本機把已打部分從卡 1 與灰字中扣除，不重新請求；一旦偏離才重新請求。

### 3.5 畫面穩定
- 打字時舊卡變淡（opacity 0.45）而非消失；新結果原地替換
- 卡片區高度固定，不因內容多寡跳動
- 卡片區固定在編輯區底部；編輯區自動捲動，保持游標在卡片區上方
- 請求失敗時靜默隱藏卡片，狀態列顯示小圓點變灰，不跳錯誤視窗

## 4. 個人化
- **語氣學習**：讀取最近 3–5 篇日記的英文定稿，生成「風格摘要」（每天第一次開啟時更新一次並快取），放入固定前綴
- **英文程度**：設定選項 初級 / 中級 / 中高級 / 高級（預設中高級），控制建議用字難度

## 5. 「整理今日日記」指令

寫完後手動執行（桌面快捷鍵、手機指令選單）。一次 API 呼叫完成：

1. 把仍是中文的句子改寫為英文，與既有英文合併成通順的**英文定稿**（盡量保留原英文句，不大幅改寫）
2. 原始混寫草稿完整收進**中文原稿**（保留原貌）
3. 當日採用過的建議與關鍵用語整理成 **Today's expressions**（英文 — 中文意思）
4. 產生 frontmatter：心情、主題標籤、相關筆記連結建議

整理前先把原稿備份到 `Diary/.drafts/YYYY-MM-DD.md`，可回復。

### 5.1 存檔格式

```markdown
---
date: 2026-11-11
type: english-diary
mood: [tired, relieved]
topics: [podcast, work, rest]
level: upper-intermediate
related: ["[[某篇相關筆記]]"]
---

## English
（英文定稿）

## 中文原稿
（原始混寫草稿）

## Today's expressions
- jump between topics — 話題跳來跳去
- took longer than I expected — 比預期花更久
```

此格式讓「我的思考區」技能可依 `type`、`mood`、`topics` 檢索，並同時取得英文內容、中文原意與學習軌跡。

## 6. 學習回顧
- 指令「產生本週回顧」：彙整本週所有 Today's expressions，存成 `Diary/Reviews/YYYY-Www.md`
- 可設定每週日開啟 Obsidian 時自動提示

## 7. 用量與成本
- 設定頁顯示：今日請求次數、輸入／輸出 token、估計費用
- 每日上限（預設 1500 次請求），超過則暫停建議並提示

## 8. 設定項目

| 項目 | 預設 |
|---|---|
| Gemini API key | （空） |
| 建議模型 | `gemini-3.5-flash-lite` |
| 整理用模型 | `gemini-3.5-flash-lite`（可改用更強模型） |
| 日記資料夾 | `Diary` |
| 英文程度 | 中高級 |
| 停頓觸發（ms） | 400 |
| 引導問題觸發（秒） | 20 |
| 顯示灰字預測（桌面） | 開 |
| 每日請求上限 | 1500 |

## 9. 隱私
- 只有書寫中的片段與摘要會送到 Gemini API；日記檔只存在 vault
- API key 存在外掛 `data.json`，README 提醒排除於 Git 同步之外

## 10. 開發階段

| 階段 | 範圍 |
|---|---|
| MVP | 桌面：建議卡、灰字、Tab/Alt 採用、§3 即時策略、整理指令、設定頁 |
| 第二版 | 手機介面（鍵盤上方卡片）、引導問題、語氣學習、英文程度 |
| 第三版 | frontmatter 標籤與相關筆記、每週回顧、用量統計與上限 |
